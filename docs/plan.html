Command Vault

Un depozit personal pentru comenzile și scripturile din munca de tehnician IT: le scrii o dată, le explici o dată, apoi le găsești în trei secunde și le ai în clipboard din două apăsări — de pe orice mașină.

Tehnologii

Stack-ul și motivul fiecărei alegeri

Totul în TypeScript, ca să nu comuți între două limbaje. Nimic exotic — fiecare piesă are documentație bună și o poți întreține singur peste doi ani.

Frontend
React + Vite + TypeScript
Build instant, ecosistem mare. Rutare cu TanStack Router, date cu TanStack Query — cache și refetch fără cod scris de mână.
UI
Tailwind + shadcn/ui
Componentele se copiază în proiect, nu se ascund într-un pachet — le modifici direct. Dialog, command palette și tabel deja accesibile.
Editor cod
CodeMirror 6
Evidențiere pentru PowerShell, bash, SQL; mult mai ușor de integrat decât Monaco. Același component, read-only la vizualizare și editabil în formular.
API
Fastify + Zod
Rapid, tipizat, cu validare din aceleași scheme pe care le folosește și frontend-ul (pachetul shared).
Acces la date
Drizzle ORM
Rămâi aproape de SQL — esențial, pentru că partea de căutare și dashboard-ul sunt SQL curat, nu magie de ORM.
Bază de date
PostgreSQL 16
Full-text search nativ (tsvector + GIN) și potrivire aproximativă (pg_trgm). Nu-ți trebuie Elasticsearch pentru câteva mii de intrări.
Autentificare
Sesiune pe cookie + argon2
Un singur utilizator la început, dar cu owner_id deja în schemă, ca să poți invita colegi fără migrare dureroasă.
Găzduire
Docker Compose + Caddy
Trei containere pe un VPS sau pe o mașină din Proxmox. Caddy ia certificatul TLS automat. Ești sysadmin — asta e partea ușoară.
Backup
pg_dump zilnic + export Markdown
Dump-ul e pentru restore rapid; exportul în fișiere .md într-un repo git privat e plasa de siguranță care se citește și fără aplicație.
Model de date

O singură tabelă pentru comenzi și scripturi

Diferența dintre o comandă de o linie și un script de 200 de linii e o coloană kind, nu o schemă separată. Altfel ajungi cu două module de căutare, două de tagging și două dashboard-uri.

schema.sql — nucleul
-- domenii ierarhice: Windows > Active Directory > Utilizatori
CREATE TABLE categories (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name        text NOT NULL,
  slug        text NOT NULL UNIQUE,
  parent_id   uuid REFERENCES categories(id) ON DELETE SET NULL,
  icon        text,
  sort_order  int  DEFAULT 0
);

CREATE TABLE tags (
  id     uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name   text NOT NULL,
  slug   text NOT NULL UNIQUE,
  color  text                          -- opțional, pentru chips colorate
);

CREATE TYPE entry_kind AS ENUM ('command', 'script');
CREATE TYPE risk_level AS ENUM ('safe', 'caution', 'destructive');

CREATE TABLE entries (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id       uuid NOT NULL REFERENCES users(id),
  kind           entry_kind  NOT NULL,
  title          text        NOT NULL,     -- singurul câmp obligatoriu la salvarea rapidă
  body           text        NOT NULL,     -- comanda sau conținutul scriptului
  language       text        NOT NULL,     -- powershell | cmd | bash | sql | cisco | mikrotik
  platform       text[]      DEFAULT '{}', -- {windows,linux,esxi,ios}
  description    text,                    -- explicația detaliată, în Markdown
  rollback       text,                    -- cum dai înapoi; obligatoriu la 'destructive'
  risk           risk_level  NOT NULL DEFAULT 'safe',
  requires_admin boolean     NOT NULL DEFAULT false,
  params         jsonb       NOT NULL DEFAULT '[]', -- [{name,label,default,example}]
  category_id    uuid REFERENCES categories(id),
  source_url     text,                    -- de unde ai luat-o: docs, KB, forum
  is_favorite    boolean     NOT NULL DEFAULT false,
  copy_count     int         NOT NULL DEFAULT 0,
  last_used_at   timestamptz,
  archived_at    timestamptz,             -- soft delete: nu ștergi niciodată de tot
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now(),
  search         tsvector                 -- întreținut de trigger, vezi secțiunea Căutare
);

CREATE TABLE entry_tags (
  entry_id uuid REFERENCES entries(id) ON DELETE CASCADE,
  tag_id   uuid REFERENCES tags(id)    ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);

-- istoricul scripturilor: o intrare la fiecare salvare care schimbă body-ul
CREATE TABLE entry_versions (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  entry_id   uuid NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
  version    int  NOT NULL,
  body       text NOT NULL,
  note       text,                        -- „am adăugat -WhatIf"
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (entry_id, version)
);

-- fiecare copiere / descărcare; alimentează dashboard-ul
CREATE TABLE usage_log (
  id       bigserial PRIMARY KEY,
  entry_id uuid NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
  action   text NOT NULL,              -- copy | download | open
  at       timestamptz NOT NULL DEFAULT now()
);

Trei decizii care contează mai târziu

Parametrii sunt date, nu text. Comanda conține {{upn}}, iar params descrie ce e upn: etichetă, exemplu, valoare implicită. De acolo iese formularul de completare și butonul „Copiază completat". E singura protecție reală împotriva rulării unei comenzi cu numele serverului greșit.

Categorie una, taguri multe. Categoria e ierarhică și răspunde la „unde stă asta?" (Windows → Active Directory). Tagurile sunt libere și răspund la „când îmi trebuie?" (troubleshooting, audit, onboarding, urgent). Amestecarea lor e greșeala clasică ce duce la 200 de taguri inutilizabile.

Nu ștergi niciodată. archived_at în loc de DELETE. Comanda pe care o ștergi azi pentru că „nu mai folosim serverul ăla" e exact cea de care ai nevoie peste opt luni.

Căutare

Modulul de căutare și filtrare

Postgres face toată treaba. Ranking ponderat, ca titlul și tagurile să bată o potrivire întâmplătoare din mijlocul unui script de 200 de linii.

Cum se construiește indexul

  • ATitlul, greutate maximă. Cauți „flush dns", primești intrarea numită așa.
  • BTagurile și numele categoriei, agregate în același vector la fiecare salvare.
  • CDescrierea — prinde întrebările de tipul „cum verific de ce nu se replică".
  • DCorpul comenzii — ultimul ca pondere, dar prezent: cauți Get-ADReplication și îl găsești.

Peste asta, pg_trgm pe titlu acoperă greșelile de tastare („ipconfig" scris „ipcofnig"), iar unaccent normalizează diacriticele din explicațiile scrise în română.

index + interogare
-- vectorul, întreținut de trigger la INSERT/UPDATE
UPDATE entries SET search =
    setweight(to_tsvector('simple', unaccent(title)),        'A')
 || setweight(to_tsvector('simple', unaccent(tags_text)),    'B')
 || setweight(to_tsvector('simple', unaccent(description)), 'C')
 || setweight(to_tsvector('simple', body),                  'D');

CREATE INDEX entries_search_idx ON entries USING GIN (search);
CREATE INDEX entries_title_trgm ON entries USING GIN (title gin_trgm_ops);

-- căutare + filtre, într-o singură interogare
SELECT e.*, ts_rank(e.search, q) AS rank
FROM entries e, websearch_to_tsquery('simple', $1) q
WHERE e.archived_at IS NULL
  AND (e.search @@ q OR e.title % $1)
  AND ($2::uuid   IS NULL OR e.category_id = $2)
  AND ($3::text[] IS NULL OR e.language = ANY($3))
ORDER BY rank DESC, e.copy_count DESC
LIMIT 50;

Filtrele din interfață

domeniu: Active Directory tag: troubleshooting + urgent shell: powershell platformă: windows risc: destructive tip: script necesită admin: da doar favorite folosite recent niciodată folosite fără descriere

Filtrele active se scriu în URL (?q=dns&tag=network&lang=powershell), ca o căutare des folosită să devină un bookmark. Ctrl+K deschide paleta peste orice ecran; ↑ ↓ navighează, Enter copiază direct, Tab deschide detaliul.

Fluxuri

Cele trei drumuri pe care le faci zilnic

1 · Am rezolvat ceva, vreau să nu uit

  • 1Ctrl+N oriunde în aplicație deschide formularul rapid.
  • 2Lipești comanda. Limbajul e detectat automat (Get- → PowerShell, #!/bin/bash → bash) și se poate corecta dintr-un select.
  • 3Titlul e sugerat din comentariul de pe prima linie; îl accepți sau îl rescrii.
  • 4Enter salvează. Descrierea și tagurile pot veni mai târziu — intrarea apare în „de completat" pe dashboard până le adaugi.
exemplu de intrare salvată
# Conturi AD dezactivate care încă consumă licență M365
Get-ADUser -Filter 'Enabled -eq $false' -Properties LastLogonDate |
  Where-Object { $_.LastLogonDate -lt (Get-Date).AddDays(-90) } |
  Select-Object Name, SamAccountName, LastLogonDate |
  Export-Csv "{{cale_export}}" -NoTypeInformation -Encoding UTF8

domeniu : Windows > Active Directory
taguri  : audit, licentiere, curatenie
risc    : safe  ·  admin: da  ·  parametru: cale_export

2 · Îmi trebuie ceva acum, sub presiune

  • 1Ctrl+K, scrii „replicare" sau „dns".
  • 2Rezultatele apar în timp real, cu domeniul și tagurile pe fiecare rând.
  • 3Enter copiază comanda și închide paleta. Un mesaj scurt confirmă; copy_count crește.
  • 4Dacă are parametri, se deschide întâi formularul — comanda nu ajunge niciodată în clipboard cu {{...}} în ea.

3 · Rulez ceva care poate strica

  • 1Intrările marcate destructive au bandă roșie în listă și în detaliu.
  • 2La copiere apare un dialog cu explicația și cu pasul de rollback, care trebuie confirmat.
  • 3Câmpul rollback e obligatoriu la salvare pentru acest nivel de risc — nu poți marca ceva distructiv fără să scrii cum se repară.
  • 4Detectorul propune singur eticheta când vede Remove-, rm -rf, DROP, format, dd if=, reset factory.

Reguli

Ce se construiește din prima, nu se adaugă pe urmă

Sunt lucruri care, odată ce baza are 300 de intrări, devin foarte scumpe de reparat.

Zero secrete în bază

Scanner la salvare care caută -AsPlainText, password=, chei API, blocuri PEM, connection strings. Blochează salvarea și cere fie înlocuirea cu un parametru, fie confirmarea explicită că e un exemplu. Baza asta va ajunge într-un backup, într-un repo git și poate pe telefon.

Nimic nu se execută din aplicație

Aplicația copiază și descarcă, atât. O funcție de „rulează pe mașina X" transformă un caiet de notițe într-un instrument de administrare la distanță — cu totul altă discuție despre securitate. Dacă o vrei vreodată, e proiect separat.

Rollback obligatoriu la risc mare

Nivelul de risc e o coloană cu constrângere, nu un tag. Nu poți salva ceva marcat destructive fără text în rollback. Regula te obligă să gândești o dată, în liniște, în loc să improvizezi la 2 noaptea.

Export citibil fără aplicație

Un job zilnic scrie fiecare intrare ca fișier Markdown cu front-matter, în structura domeniilor. Dacă aplicația cade, dacă baza se corupe, dacă te plictisești de proiect — cunoștințele rămân într-un folder pe care îl citește orice editor.

Import din ce ai deja

Prima zi de folosire nu trebuie să înceapă cu o listă goală. Un importator care citește istoricul de PowerShell și bash, plus fișiere .md și .txt, îți dă 50 de intrări de curățat în loc de zero de scris.

Taguri controlate

Autocomplete la scriere, cu tagurile existente propuse primele, și un ecran de administrare unde poți redenumi sau uni taguri. Fără asta ajungi la retea, rețea, network și net pentru același lucru.
